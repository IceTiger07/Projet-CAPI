## 1. CU-01 : Estimer le backlog d'un projet

| Rubrique | Contenu |
|---|---|
| **Portée et niveau** | application CAPI · utilisateur |
| **Acteur principal** | Joueurs |
| **Intervenants et intérêts** | **Scrum Master** : veut garantir le respect des règles. **Product Owner** : veut garantir que les taches sont bien estimé |
| **Déclencheur** | Les joueurs lancent le jeu |
| **Garanties** | **Minimales** : Les taches ont toutes une estimation. **De succès** : Les taches ont toutes une estimation optimale  |

### Scénario nominal (5 à 7 étapes)

1. Les joueurs configurent la partie.
2. Les joueurs choisissent quelle backlog doit être chargé
3. L'application decrypte le fichier JSON et récupère les informations nécessaire au déroulement de la partie
4. Les joueurs estiment pour une user stories
5. Les joueurs débattent sur leurs estimation des user Stories et peuvent ensuite estimer de nouveau
6. Les joueurs passent à l'user stories suivante et répète le processus pour toutes les user stories
7. L'application enregistre un fichier JSON avec pour chaque fonctionnalité la difficulté estimée.

### Extensions (3 obligatoires)

- **<étape>a.** Le backlog chargé est invalide :
  - <étape>a1. L'application affiche un message d'erreur
  - <étape>a2. L'application demande la saisie d'un nouveau backlog
- **<étape>b.** Tous les joueurs jouent la carte café :
  - L'application sauvegarde l'état d'avancement dans un fichier JSON
- **<étape>c.** L'utilisateur reprend une partie sauvegardée :
  - L'application récupère les informations nécessaire à la poursuite de la partie et fais reprendre la partie là où elle s'était arrèté

## 2. Les 6 user stories

| US | Texte (En tant que... je veux... afin de...) | Source | MoSCoW |
|---|---|---|---|
| US-01 | En tant que joueur, je veux l'unanimité afin de valider la difficulté d'une fonctionnalité | | |
| US-02 | En tant que joueur, je veux faire une moyenne des difficultés au second tour afin de valider la difficulté d'une fonctionnalité | | |
| US-03 | En tant que joueur, je veux l'unanimité dès le premier tour afin de valider la difficulté d'une fonctionnalité | | |
| US-04 | En tant que joueur, je veux configurer une session de planning poker afin de charger un backlog et pouvoir jouer | | |
| US-05 | En tant que joueur, je veux voter avec une carte afin de s'exprimer sur la difficulté d'une fonctionnalité | | |
